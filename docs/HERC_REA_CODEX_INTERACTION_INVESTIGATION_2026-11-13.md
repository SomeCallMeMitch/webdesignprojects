# Herc Magnus desktop interaction investigation

2026-11-13 PST · Public browser research for the unofficial Keith Tyran desktop concept

## Executive summary

**DIRECT OBSERVATION.** At 929 × 965 CSS px, mouse drag changed the native range at every tested value in both directions. Click-to-seek, endpoint labels, Arrow Left/Right, Home and End worked. The rendered knob and scene lagged the input. The rock cutout faded over a speaking-stage photograph that contains the speaker. The separate speaking image element remained fully transparent throughout. The hero CTA stayed the same across the tested positions. Warm amber and cool blue beams tracked the pointer on the rock side. At the speaking endpoint no comparable moving beams were visible.

**SCRIPT/STYLE SUPPORTED.** The hero uses Canvas 2D to reveal lit photographs, composite procedural haze and draw moving cones and light pools. Six beam origins are fixed to coordinates on the rock-stage photograph. The renderer moves beam targets and adds fixture bloom. No independent rotating fixture-head artwork was established. Keith’s three visible rotating heads have a separate design requirement.

**SCRIPT/STYLE SUPPORTED.** Normalized window mouse coordinates add 6%/4% horizontal/vertical offsets to ambient photo targets. Hover blends toward the canvas-local pointer via a 7%-per-frame approach. Fixture-specific damping uses a time constant between 260 and 480 ms with frame delta capped at 64 ms. Pool radius is at least 60 CSS px, then increases with source-to-target distance. No stage-angle clamp was found in this hero loop. The renderer illuminates the dark plate with masked lit imagery via quarter-resolution masks and haze, a half-resolution lit plate and the main canvas. Layered, shaded polygons make the cones, radial gradients make pools and glow, and smoke uses blurred cone-shaped masking and blend operations. These are decorative 2D light fields, with no physical floor intersection test established. The beam can track the pointer even above the floor. The source paints bloom over photographed fixtures, with no synchronized rotating fixture graphic found in this path.

Layer availability remains unverified.
2. Use a labelled native range. Keep its input and handle responsive and progress reversible, with visible focus and accessible values describing both poses. Use one scalar to crossgrade original state lighting and a narrow light-assisted reveal around the handoff. Compare this against a short crossfade using the actual pose assets, especially hands and faces at 25/50/75%. Keep navigation and CTA independently usable. This treatment is provisional.
3. Use one stage coordinate system for the plate, fixture sprites and an original SVG overlay. Give each visible overhead mount one pivot. Compute one bounded, damped angle per head, with its cone axis tied to the same transform and its apex at the emitting lens throughout the turn. Use a shared transformed group or derive both the aim and lens position from that same angle if the lens is offset from the hinge. Keep beam ends below the heads and inside the stage region. Add restrained floor pools and optional haze behind the portrait and seats as appropriate. Track the stage region only and ease to an intentional resting pose on leave. Under reduced motion, hold the beams still and switch the portraits immediately.
4. Start with CSS/SVG transforms, opacity and a single elapsed-time `requestAnimationFrame` loop. Stop work when settled, offscreen or hidden. Predecode the two pose images and profile at 1672 × 941 plus the approved desktop review sizes. Three localized cones are a smaller rendering problem than recreating Herc’s per-frame photo masks. Profile SVG blur and blend costs before adding effects. A timeline library such as GSAP becomes useful only if an approved multi-stage sequence needs coordinated scrubbing and interruption beyond this simple state map. It still leaves pivot geometry and rendering costs to the implementation.
5. Before implementation, validate pose alignment and rights, lens and hinge coordinates, cone-free stage art and the approved degree of sweep. Once the user authorizes a build, verify static composition first, then the keyboard and slider matrix, then fixture/head alignment at all sampled targets and states, followed by reduced motion, CTA contrast and a presented-frame performance trace.
