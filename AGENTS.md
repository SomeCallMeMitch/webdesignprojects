# Repository instructions — mandatory for every AI agent and chat

## Startup protocol (non-negotiable)
1. Identify the current branch and confirm the requested project. Do not write to main unless explicitly authorized.
2. Read this file, then `docs/PROGRESS.md`, `docs/DESIGN_PREFERENCES.md`, `docs/PROJECT_BRIEF.md`, `docs/REFERENCE_SITE_ANALYSIS.md`, and `docs/PROSPECT_RESEARCH.md` before proposing or changing anything.
3. Check the current file tree and the latest branch commit. Reconcile any contradictory or stale information instead of silently assuming.
4. Summarize current state, open decisions, and what's already completed. Ask only genuinely consequential questions.
5. Respect project mode: planning/research/design versus coding. NO implementation, deployment, domain work, live contact, or publishing unless explicitly approved.
6. At the end of EVERY task or prompt, update `docs/PROGRESS.md` on the current branch with an append-only dated entry: work requested; actions completed; files changed; evidence/links; decisions and rationale; open questions; exact next actions; commit/branch; whether anything was deployed or anyone contacted.
7. If work stops or a tool fails, write a status/blocker entry to PROGRESS before finishing whenever repository write access exists. If not, provide the complete proposed entry in chat for a future write.
8. Any durable decisions about visual style, UI, accessibility, motion, audio, navigation, or reusable patterns must also be recorded in `docs/DESIGN_PREFERENCES.md`. Distinguish user-approved decisions from concepts and provisional suggestions.
9. For research, record date, source URL, exactly what the source demonstrates, and what remains unknown. Never turn assumptions, cached social counts, or promotional claims into verified facts.
10. Before finishing, reread PROGRESS and report the branch, paths, commit SHA and any uncompleted items.

## Preferred workflow
- ChatGPT Chat or Work: discovery, UX strategy, comparative research, information architecture, critique, planning, design briefs.
- Codex: implementation after scope/design approval; tests, cross-device verification and technical review. Claude is also acceptable.
- Small, reviewable phases with screenshots/live previews and explicit human approval before significant changes.
- Keep documents simple Markdown, use descriptive file names, no hidden local-only handoffs.
- Work may span multiple chats: repository documents, not chat memory, are the system of record.
